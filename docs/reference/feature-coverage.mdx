# Explore the feature map

Tracexy starts with a **session** and leads to the frames that support it. Explore a feature in its own guide, or open one of the coverage areas below to check a familiar Wireshark workflow. **Available** means a supported Tracexy action, **Partial** means narrower coverage, and **Coming soon** means unavailable today with no promised date.

## Wireshark workflow coverage
| Wireshark workflow | Tracexy status | Scope |
| --- | --- | --- |
| Packet list, details tree, hex/bytes pane | Partial | All Frames pages through a stable capture with at most 200,000 retained rows per scan; Frame Expression counts matches across the capture and shows them by page, while toolbar search applies to the current page. Optional Relative TCP Seq/Ack displays capture-order relative values in All Frames only, bounded to 200,000 conversations; raw protocol facts and filtering remain unchanged, and ACK stays unknown until its reverse-direction origin is observed. Up to 16 capture-local pinned rows stay in a separate strip across paging and filters, with go-to and unpin actions. Session and standalone frame-details trees filter decoded layer titles/summaries and field names/values by substring, preserve byte mappings, recursively expand/collapse subtrees, and copy a layer's visible subtree while honoring folded descendants and the displayed projection. Both trees navigate with arrows, Return, Shift+Arrow and Command+Arrow while focused. Double-clicking a frame with no folded session opens a frame-scoped details tree beside its exact hex bytes without inventing a session. The packet-list context menu and bytes pane copy complete frame bytes in hex/text formats or raw `application/octet-stream`; the bytes pane also copies selected fields. The CLI `frames` table streams every row of a complete stable capture. |
| Search/find packet, go to frame, related packets | Available | Bounded text/hex/regex and Frame Expression Find scan the stable capture and navigate across pages without changing the applied filter; expression search counts frames whose facts are unknown and reports a truncated tail. String/Bytes supports UTF-8, UTF-16 LE, UTF-16 BE, or all three encodings. Toolbar search remains page-local. All Frames has bounded Back/Forward selection history with guarded filter and paging behavior, First/Last on the current page, and frame/session navigation. |
| Packet marking, ignoring, comments | Available | Local investigation controls including Mark/Unmark All Displayed and Ignore All Displayed for the current visible result, read-only on-demand display of selected PCAPNG source comments, Tracexy-authored frame comments on explicit export, and optional capture-export exclusion of ignored ordinals. |
| Custom columns, layout, colorization | Partial | Custom session columns, native layout, a temporary page-local Frame Expression highlight, up to ten capture-local conversation color slots, and ordered Project-local packet coloring rules with foreground/background colors and draft-only duplicate actions. Import accepts Wireshark `coloring_rules.jsonc` and legacy `colorfilters` records only when filters fit Tracexy's bounded grammar; unsupported rules are reported. Profiles and display-filter semantics are not imported. |
| Decode As and enabled protocols | Partial | Project-local TCP/UDP port overrides and protocol enable/disable; All Frames and packet-details TCP/UDP context menus can prefill a reviewed, unapplied source- or destination-port rule. The read-only CLI accepts up to 64 invocation-local `--decode-as udp:5300:dns` rules on decoding verbs, including summary, and never loads or changes Project settings. An existing same-port rule is replaced on Apply; no universal dissector dispatch or TShark `-d` grammar. |
| Checksum validation and malformed-packet hints | Partial | Opt-in IPv4/TCP/UDP/SCTP/ICMP/ICMPv6 checks and bounded decode warnings; no universal expert validation. |
| Name resolution and address book | Partial | Project-local address names can be added from Sessions or an All Frames packet row, merged from an explicitly selected standard/Wireshark `hosts` file (bounded to 256 KiB, 10,000 lines and 500 addresses), or read from PCAPNG Name Resolution Blocks up to 64 KiB and 500 mappings (omitted records/blocks are reported in Capture Info). DNS/mDNS answer facts remain separately attributed. Existing Project labels win in All Frames. A MaxMind-format GeoIP/ASN database you already have can be added per Project from **Statistics → GeoIP Databases…**, read locally only, adding Country/City/AS columns, a GeoIP inspector layer and `$geoip_*` Session Expression macros. No automatic profile discovery, external DNS, bundled database, or broad Wireshark resolver parity. |
| Time references, shift and display formats | Partial | Selected frame time controls distinguish previous displayed from previous captured packets, preserve unknown deltas, use the first packet's timestamp as capture origin, and support up to 16 temporary references. All Frames references are capture-wide, remain visible across pages and display filters, and can be navigated; its optional Cumulative Bytes column sums captured lengths capture-wide and resets at each reference frame. Session Frames also supports session-scoped references. Saved captures support an in-memory whole-capture offset, one frame/time anchor or two anchors for linear drift, with Undo; sessions, findings, evidence, timelines, All Frames and Follow views are recomputed from the same overlay. The original file remains unchanged; Save Capture and supported PCAPNG exports carry the correction and provenance. Live capture shifting and full Wireshark profile/time-field compatibility remain unavailable. |
| Field-level packet display filters and macros | Partial | All Frames supports a bounded Frame Expression subset over typed per-frame facts, including capture-interface direction (`frame.capture_direction == inbound` or `== outbound`, with absent metadata remaining unknown), `ip.addr`/source/destination matches across decoded outer and inner IPv4/IPv6 tunnel headers, observed TCP control flags and raw sequence/acknowledgement equality, IPv4 Identification equality and a Don’t Fragment predicate, per-header IPv4 TTL / IPv6 hop limit numeric comparisons, IPv4 fragment more / byte-offset predicates, DNS response/rcode/transaction-ID/truncation fields, and ICMP/ICMPv6 type/code equality. The session decode tree can copy a supported standalone field term, highlight matching frames temporarily, or apply/prepare supported unique-layer TCP FIN/SYN/RST/PSH/ACK/URG/ECE/CWR flags, DNS IDs and TC flags, IPv4 Identification/address/TTL/fragmentation/Don’t Fragment, IPv6 address/hop-limit, ICMP/ICMPv6 type/code, directional TCP/UDP port, and TCP window/sequence/acknowledgement predicates as Frame Expressions; Session Expressions remain separate. Choosing a preset fills the draft and requires explicit Apply. Transport port terms `tcp.port`/`srcport`/`dstport`, `udp.*` and `sctp.*` are supported. Macros exist for Session Expressions only, so there are none for packet filters; there is no general field registry and no Wireshark grammar compatibility. |
| Wireshark profiles, coloring-rule sets, and preferences import | Partial | Coloring rules can be imported from user-selected JSONC and legacy `colorfilters` files when filters fit Tracexy's bounded grammar; rules append to the Project draft and unsupported rules are reported. A Wireshark `dfilters` file imports as saved Session Expressions and a `cfilters` file as capture filters, in both cases reporting what could not be translated. Full profile import and preference compatibility remain unavailable. |

| Wireshark workflow | Tracexy status | Scope |
| --- | --- | --- |
| Conversations and endpoints | Available | Session-first tables, host/endpoint projections, app context when observed. |
| Follow TCP/UDP/application stream | Partial | On-demand bounded follow for stable sources and selected protocols; TCP export keeps attributed source chunks and per-peer YAML indexes. When retained provenance cannot prove cross-direction order, bidirectional Save/Copy/Print is disabled with a reason while one-direction Save/Print stays available in TCP sequence order with unknown frame metadata explicit. UDP transcripts can filter retained rows by direction, and retained datagrams can be saved as bounded YAML or concatenated raw payload when completeness checks pass; both TCP and UDP conversations can be excluded from the session view with a Session Expression. Raw export loses datagram boundaries and does not prove complete network capture; no universal stream dissector. |
| Protocol hierarchy, capture summary, packet lengths | Available | Scope-aware Overview and Statistics views. |
| I/O graphs, flow graph, timeline | Partial | Traffic timeline and supported graphs. I/O Graph compares up to four independently named/enabled Tracexy Frame Expression series in one complete stable-source pass, on a shared bounded time axis. It preserves capture extent, reports per-series match/unknown/untimed coverage, zero-fills empty intervals, and supports CSV/chart-image export; interval changes reproject the bounded aggregate without rescanning. A chart interval can select a representative matching frame in All Frames through a Project/generation/source-token-guarded request. Show All Traffic restores the unfiltered live graph. Series count independently when filters overlap. Arbitrary Wireshark field calculations, secondary axes, moving averages and profile persistence remain unavailable. |
| TCP stream graphs and deep sequence analysis | Partial | Selected lifecycle, retransmission, RTT/flow-control evidence; overlapping retransmissions invalidate pending cumulative-ACK RTT candidates under Karn's algorithm and excluded candidates are counted. A separate SACK-reported RTT line conservatively matches the first retained SACK block to one exact, non-overlapping captured payload range; both frames are cited, and repeated reports do not duplicate a sample. This reports receiver observation, not application delivery, and is not a claim of Wireshark algorithm parity. A stable-source action can rescan one TCP conversation up to 65,536 decoded segments, while each chart draws at most 1,024 observed points per line and reports the displayed/total count. Sequence plots each captured payload byte interval and its exclusive edge, as well as reached and cumulatively acknowledged edges; payload ranges crossing the relative sequence half-space are counted and omitted. Up to four receiver-reported SACK ranges per ACK are overlaid at the citing ACK time in the peer's relative sequence space; RFC 2883 D-SACK first blocks are shown as separately styled ranges only when the same-packet cumulative ACK places them wholly below its edge, or places them wholly above it and the second SACK block contains them. The chart names this as a receiver report and does not infer cause. Ranges whose edges cannot be placed in one unambiguous half-space are counted and omitted. The Throughput chart includes wire-byte rate and SACK-aware receiver-ACKed sequence-space Goodput, de-duplicating overlapping blocks and cumulative ACK coverage and excluding RFC 2883 D-SACK block patterns from new-byte credit. D-SACK expert findings, tcptrace graph, and the full set of Wireshark TCP plots remain unavailable. |
| Expert information | Partial | Evidence-linked selected findings with explicit coverage limits plus typed TCP window-update and zero-window probe observations; not a general expert engine. |
| HTTP, DNS, IP, service response, distribution statistics | Partial | Selected statistics trees and views over supported decoded traffic. SMB2, LDAP, Kerberos, ICMP and ICMPv6 SRT in the window and CLI rescan the complete stable capture; session scope is independent of All Frames paging. Echo SRT refuses a result if any required session/address/timestamp fact is missing or if pending requests or exact duration samples exceed 200,000, preserving bounded memory and exact reported medians. LDAP currently recognizes the first message per segment, without TCP PDU reassembly. |
| Telephony: SIP, RTP, VoIP calls, multicast | Partial | Selected SIP/RTP/multicast views; broad telephony analysis, playback, and all codecs remain unavailable. |
| Wireless: 802.11, radiotap, WLAN decryption, Bluetooth | Coming soon | No broad radio-layer analysis or key management. |
| Protocol-specific statistics for the full dissector catalog | Coming soon | Coverage is limited to the protocols listed in the app and [protocol reference](/reference/protocols). |
| Arbitrary plots, taps, Lua and dissector plugins | Partial | **Statistics → Plot…** charts one decode-tree field over time and **Statistics → Value Distribution…** counts one field's values, both over a complete pass of a stable source. Arbitrary Wireshark field calculations, Lua, and a compatible plugin/tap execution model remain unavailable. |

## Protocols and content

| Wireshark workflow | Tracexy status | Scope |
| --- | --- | --- |
| Ethernet/VLAN, cooked/loopback/raw IP, ARP, IPv4/IPv6, ICMP, TCP/UDP | Available | Bounded decode; supported IPv4/IPv6 fragment reassembly. |
| DNS, TLS, HTTP/1, STUN, QUIC | Partial | Selected metadata and explicit follow views; QUIC long headers only. |
| SCTP | Partial | Common header endpoints, verification tag, raw CRC32C and at most 64 bounded chunk headers are decoded, with DATA TSN and PPI; chunks past the retention limit are flagged as omitted rather than counted. **View → Validate Checksums** verifies CRC32C only when the IP-declared packet boundary is fully captured. SCTP flows fold into sessions on their endpoint pair, with directional packets and bytes, and appear in the SCTP tab of **Statistics → Conversations** and **Statistics → Endpoints** (`--tap conv,sctp`, `--tap endpoints,sctp`). `sctp.port`, `sctp.srcport` and `sctp.dstport` filter All Frames, SCTP port rows in the decode tree offer Apply as Frame Filter, and Wireshark `sctp` port filters translate into Session Expressions. An observed INIT chunk names the side that opened the association, and an observed ABORT marks the session as an error. Grouping is per endpoint pair, not per association: the verification tag is decoded but not used as session identity, so successive associations on one port pair share a session. Stream reassembly and Follow for SCTP are absent. |
| HTTP/2, WebSocket, mail, SSH, local services, tunnels | Partial | Selected cleartext and on-demand paths; coverage depends on source and protocol. |
| HTTP/3, deep QUIC, encrypted HTTP content | Coming soon | No QUIC or TLS decryption. |
| Complete Wireshark protocol dissector catalog | Coming soon | Tracexy has a deliberately bounded selected set. |
| TLS/QUIC decryption and key-log workflows | Coming soon | Encrypted application bytes are not exposed. |
| Export Objects and upper-layer PDUs | Partial | Selected supported protocols and reconstructed objects, with completeness limits. FTP file bytes use the command's sender direction in TCP sequence order; control streams with unknown command/reply chronology are counted and skipped. Upper-layer PDU export omits and counts TCP streams whose retained frame provenance cannot prove cross-direction order. |
